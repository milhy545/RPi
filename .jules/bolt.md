## 2024-08-08 - [TUI Performance Optimizations]
**Learning:** Found two clear performance bottlenecks during TUI rendering loops inside `SystemMetricsMixin` in `tui.py`. The `get_local_ip` function was resolving a UDP socket connection every tick (every 2s by default). Also, `get_ram_usage` was unnecessarily parsing the entire `/proc/meminfo` file after finding its target values on the first two lines.
**Action:** Implemented a 60s class-level cache (`_cached_ip`, `_cached_ip_time`) for `get_local_ip` reducing overhead from ~0.012s to ~0.0002s per tick. Added an early exit `break` loop condition in `get_ram_usage` reducing execution time by ~40% per call. Ensure IP caching logic falls back to subclass storage (`type(self)`) for safety. Ensure file I/O early exits are used whenever possible to save CPU cycles on low-resource hardware like the Raspberry Pi.
## 2024-08-08 - [TUI Process Creation Overhead]
**Learning:** Found a major performance bottleneck in `tui.py` when polling the system for WiFi/hotspot stats. The code was using `asyncio.create_subprocess_shell` to execute simple commands like `grep` and `cat | wc -l`. On low-resource hardware like the Raspberry Pi, creating a new subprocess is incredibly slow (~0.035s per shell) and blocks the async loop unnecessarily.
**Action:** Replaced expensive shell subprocess calls with native Python file I/O operations (`open`, `read`, parsing strings). This reduced the execution time for those specific checks by roughly 1000x and avoids blocking the event loop with heavy `fork()` calls. When polling for simple text data in files (like `/etc/hostapd/rpi-service.conf` or `/var/lib/misc/dnsmasq.leases`), always use native Python file handling instead of shelling out to Unix utilities.
